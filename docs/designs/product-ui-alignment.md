## Problem Statement

Aspiring screenwriters learning craft cannot afford professional script coverage ($50-200+ per script). They need expert-level feedback grounded in actual screenwriting theory (McKee, Snyder, Field, Swain) to improve their craft — but current AI tools (ChatGPT) give generic, ungrounded advice with no verification against the actual script text.

Script Doctor solves this with a local, privacy-first analysis system that runs 34 attributed craft rules against the script, verifies every quote, and returns a verdict the writer can argue with. The product's core value is **craft intelligence** — the tool sees what the writer misses.

## Demand Evidence

- **Primary user (founder):** Active daily user. Uses the system for their own screenwriting work. The product was built because the founder experienced the pain directly.
- **No external users yet.** Pre-product stage. No beta testers, no paying customers.

**Assessment:** Self-use is the strongest starting signal — the founder knows the pain firsthand. But self-use is not demand. The next step is getting 3-5 aspiring screenwriters to use it and measuring whether they come back.

## Status Quo

Screenwriters currently use **ChatGPT and general AI tools** for script feedback. This gives:
- Generic writing advice (not screenwriting-specific)
- No grounding in craft theory (no McKee, Snyder, Field references)
- No verification against the actual script text (hallucinated quotes)
- No structured analysis (just "here are some notes")

**What that costs them:** They get feedback that sounds smart but doesn't actually help them improve. They can't tell if the AI is right or wrong. They don't learn craft principles — they just get vague suggestions.

**Script Doctor's gap:** 34 attributed rules from craft theory masters, verified quotes, structured analysis by category (theme, character, structure, dialogue, scene function, plot economy), and a co-writer grounded in the actual draft.

## Target User & Narrowest Wedge

**Target user:** Aspiring screenwriters learning craft. They:
- Are studying screenwriting (books, courses, YouTube)
- Can't afford professional coverage
- Need expert feedback to improve between drafts
- Want to understand WHY their script doesn't work, not just THAT it doesn't

**Narrowest wedge (what someone would pay for this week):**
A single script analysis that returns a structured report with:
- Overall craft score
- Category-by-category findings (theme, character, structure, dialogue, pacing)
- Each finding attributed to a specific craft rule (McKee — Setup/Payoff, Field — Scene Function, etc.)
- Verified quotes from the script supporting each finding

**Price point:** $5-15 per analysis (comparable to a coffee, 10x cheaper than human coverage).

## Product-UI Alignment: Three Principles

### 1. Craft-First Navigation

**Current UI:** Organized by surfaces (desk, co-write, feedback, ideas). This is the technical architecture, not the user's mental model.

**Proposed UI:** Organized around craft questions the writer is asking:
- "What's wrong with my dialogue?" → Dialogue analysis
- "Is my Act II sagging?" → Pacing/structure analysis
- "Am I violating setup/payoff?" → Rule-specific findings
- "How does this scene compare to the best practices?" → Scene function analysis

The command palette (⌘K) should surface craft questions first, not file operations. When a writer opens the palette, they should see: "Why doesn't my opening work?" not "Export report."

### 2. Mentor-Led Experience (Sameer as Character)

**Current UI:** Sameer is a chatbot label. The co-write surface is a generic chat interface.

**Proposed UI:** Sameer is a craft mentor with a personality:
- Speaks in screenwriting language, not generic AI language
- References specific craft rules by name ("McKee would call this a gap between expectation and result")
- Challenges the writer ("You're telling us Mara is sad instead of showing us")
- Celebrates good craft ("This line does so much quiet work — Dev apologizing with oranges")

The UI should feel like sitting across from a knowledgeable screenwriting teacher, not using a chatbot. The welcome screen says "Evening, Avi" — that's the right tone. Extend it to every interaction.

### 3. Progressive Revelation

**Current UI:** All features visible at once (desk, co-write, feedback, ideas, export). Overwhelming for a beginner.

**Proposed UI:** Depth reveals itself as the user learns:
- **Level 1 (Upload):** Upload script → get overall score + top 3 findings. Simple, encouraging.
- **Level 2 (Explore):** Click a finding → see the craft rule, the verified quote, the suggestion. Learn one thing deeply.
- **Level 3 (Deep dive):** Full coverage report with all categories, fix queue, co-write suggestions. For the writer who's ready.
- **Level 4 (Master):** Beatwall spatial view, character tracking, theme analysis. For the writer who wants to see the whole structure.

Don't show the fix queue until they've engaged with a finding. Don't show the co-writer until they've understood the analysis. Let the product teach them how to use it.

## Constraints

- **Local-first:** Runs on the user's own llama-server. No cloud dependency. Privacy is a feature, not a limitation.
- **Offline-capable:** Once the model is loaded, everything works without internet.
- **Format support:** Must handle .fdx, .fountain, .pdf, .txt, .md — the formats screenwriters actually use.

## Premises

1. **Craft intelligence is the moat.** Every competitor can do "AI script feedback." Only Script Doctor does verified, attributed, theory-grounded analysis. This is the product, not a feature.
2. **Aspiring screenwriters are the wedge.** They can't afford human coverage and they're actively learning. They'll pay for expert feedback if it actually teaches them something.
3. **Privacy matters.** Screenwriters are protective of their work. Local-first is a genuine advantage, not just a technical choice.
4. **The UI should feel like a mentor, not a tool.** The product's personality is Sameer — knowledgeable, direct, grounded in craft theory. The UI should reflect that everywhere.

## Approaches Considered

### Approach A: Dashboard-first (current direction)
Organize around a dashboard with stats, findings, and tools. Clean, professional, but cold. Doesn't project craft intelligence.

### Approach B: Chat-first (like current co-write surface)
Organize around conversation with Sameer. Personal, engaging, but hard to structure analysis. Users lose track of findings.

### Approach C: Craft-journey-first (recommended)
Organize around the writer's craft journey: upload → discover → understand → improve → iterate. Each step reveals deeper craft insight. The UI teaches while it analyzes.

## Recommended Approach

**Approach C: Craft-journey-first** with all three principles (craft-first nav, mentor personality, progressive depth).

The UI should feel like this:
1. Writer drops a script → Sameer says "I read your draft. Here's what I noticed." (warm, specific, craft-grounded)
2. Writer sees overall score + top findings → clicks one → learns the rule, sees the quote, understands the suggestion
3. Writer asks "how do I fix this?" → Sameer suggests a rewrite grounded in the draft
4. Writer iterates → re-analyzes → score improves → feels progress

The craft journey IS the product. The UI should make that journey visible, not hide it behind technical surfaces.
