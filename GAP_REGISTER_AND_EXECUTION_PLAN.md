# Screenplay Studio — consolidated gap register and execution plan

**Purpose:** one place to see what we found across the writer journey, feedback quality, Sameer/Sushruta and supporting foundations; how we know; and what to do next. This is a planning/review artifact, not proof the entire application has been audited or fixed. Application changes have **not** started. The desired order is complete review → adversarial critique and agreement → implementation and validation.

## Evidence and test baseline

- **Full default pytest collection:** 2,248 passed, 4 skipped, 2 warnings in 97.10 seconds, using a freshly installed locked CI environment. The skipped cases are platform/applicability skips; browser E2E scripts named `e2e_browser_*.py` are not included in pytest's default collection. The suite sets the model-backed observation pass off by default except in its own tests. Many tests use mock services. Passing does not disprove the separately reproduced gaps.
- **Tracked inventory:** 665 files, including tests, documentation and assets. All 263 knowledge-base rules were mechanically inventoried; this is not a full expert review of each rule or a complete line-by-line audit of all files.
- **Real scripts:** both supplied PDFs were locally parsed and reviewed in selected passages; parser and context limitations were probed. No real model was run. A handful of paths were tested with fabricated inputs, fake clients, controlled failures or test clients; do not extrapolate frequency.
- **Unvalidated:** audience reception, real model quality/latency, cross-platform browser behavior, production incident frequency, comprehensive migration/restore safety and writer/consultant acceptance. All prior concept images are exploratory, not approved designs.

## Cross-cutting decisions

1. **Safety first, not visual polish first.** Findings 1–6 protect writer work, privacy and the truthful connection between a draft and its report. Failure of any is a stop-ship issue. Archive credentials and cross-process safety are also release-critical.
2. **A snapshot must be real, not only a label.** Capture the working draft and associated state coherently, keep inference outside the editing lock, and verify the active revision at publish. The existing per-file atomic writers do not create an atomic multi-file transaction.
3. **A reading is not a verdict.** Preserve evidence, uncertainty, counter-readings and creative intent without requiring Sushruta to agree. Sameer leads with thinking, not solutions, except on explicit request.
4. **Don't fix accuracy by deleting all hard cases.** Retain reviewable uncertainty and benchmark important missed notes alongside false alarms. Keep multilingual experts and writer intent separate from audience-response claims.
5. **Do not equate “model independent” with guaranteed quality on any model.** Evaluate multiple compatible models/hardware and report quality, variation and latency separately; do not tune to exact wording.

## One coordinated execution plan — pending the critique and approval gate

### Phase A — data safety and trust boundary
- Reproducible regression suite first for all confirmed data-loss/publication/cancellation/backup/race cases; preserve existing fixtures and demonstrate failures against current behavior.
- Design immutable working revisions, run IDs, cross-process coordination, generation publication, cancellation/retry behavior, recovery and backwards-compatible access; include backup redaction and restore policy. Define lock order and crash semantics. Preserve prior data and ambiguous legacy marks.
- Verify via actual API + CLI, two OS processes, concurrent editing, injected failure at each write, process termination/restart, disk limits, and restore. No release while a stop-ship case remains.

### Phase B — evidence, retrieval and analysis quality
- Carry exact snapshot/version and per-pass coverage into findings and chat; restore complete relevant context with bounded, measured scene windows. Resolve parser ambiguity visibly. Implement quote-match vs claim-support separation, conservative post-enrichment checks and audit trails.
- Review KB selection, assumptions, confidence language, exceptions, language filters and applied severity. Test the two scripts plus a diverse, consented held-out corpus, preserving deliberate ambiguity and independent critique.

### Phase C — collaborators and memory
- Typed neutral handoff; stable evidence/claim IDs; preferences and project scope with concurrency-safe suppression/delete; distinct personas and request-aware suggestion behavior. Check both user control and Sushruta's ability to disagree.

### Phase D — writer experience and evaluation
- Prototype one cohesive, accessible reading/discussion/revision journey, showing where each moment occurs. Test with writers and consultants before committing to the arrangement. Measure real-model quality, utility, important-issue recall, agency, privacy, completeness and latency on declared hardware and multiple configurations.
- Release incrementally behind migration/rollback controls. Assess regressions and record a clear no-go if any data-safety, privacy or misleading-evidence gate fails.

## 16–17: findings from the continued repository sweep

**16. Watch-folder processing can overwrite source files — release blocker for watch mode.** In an isolated temporary-directory test, `ProjectManifest.create` was made to fail with a simulated disk error before making a project copy. The actual `process_pending()` moved the failed screenplay to `done/`; a later failed file with the same name replaced that first source on this Linux environment. No project copies existed. The source explains why: it moves on both success and failure and `shutil.move` targets the unchanged filename. In a separate test where a project copy had already been created, that copy survived, so loss depends on the failure point. This is not a claim that the same overwrite semantics apply on every OS. **Recommended:** never treat failed work as completed; preserve the original until a verified durable project copy exists, use collision-safe no-clobber moves with explicit failure/retry and cross-process claiming, and test same-name files, partial copies, permission/disk failures and restart on supported platforms. Until fixed, avoid watch mode for irreplaceable source files and keep independently verified copies. **FIXED 2026-11-05** (critique S51). *Reproduced as three defects, each on a real filesystem:* (A) `shutil.move` reused the filename, so two different scripts dropped as `draft.fountain` left one file in `done/` and the earlier source was gone; (B) the move was gated on `ok or error`, so an ENOSPC in `ProjectManifest.create` cleared the inbox and filed the unprocessed script under `done/` with no project copy anywhere; (C) the same gate was reached through `manifest.save()`. *Fixed:* collision-safe filing via an `O_CREAT` + `O_EXCL` reservation (`draft_2.fountain`, never an overwrite); a failed drop goes to `failed/` with a `.error.txt` saying why and that the source is intact and retried by moving it back; each drop is claimed by an atomic rename into `.processing/` before any work, so a second worker or a racing poll cannot process or file it twice; and the per-file record reports `filed` so the CLI loop prints the truth. *Pinned:* `tests/test_watch_source_safety.py` (11 tests, incl. a two-thread claim race). Reverts per defect: 2 / 3 / 2 failures. No auto-retry by design — a permanent error must not spin.

**17. Browser accessibility/security tests and unload saving need follow-up.** The existing live-region suite failed the repeated-identical-error DOM-write assertion twice (21 passed, 1 failed each). The app's `showError` writes the same text again, while the observer records current DOM state rather than directly proving screen-reader announcements; this failure alone does not establish whether assistive technology announces it. Verify with a reliable mutation test and real screen readers while maintaining visible, nonempty error text. The XSS suite failed a dashboard raw-HTML substring assertion twice (35 passed, 1 failed); diagnostic inspection showed `<img` in a **quoted title attribute**, not an image element, with no executable nodes, handlers or execution detected. The current failure appears to be an overly broad serialization check, **not a demonstrated XSS vulnerability**; retain the structural probe and improve test precision. The idea pagehide/autosave suite failed once when run alongside several browser suites (`len=0`), then passed in an isolated rerun (17/17). This is an intermittent test or product risk, not yet a confirmed deterministic data-loss bug. Stress-test unload, slow/network-failure and concurrent saves; avoid asserting that a keepalive request guarantees delivery. All these browser runs use the temporary Chromium setup and repository demo/fixtures, not a full accessibility, security or real-model audit. **PARTLY FIXED 2026-11-05** (critique S52). *(a) XSS leg — fixed, and the register's diagnosis is now proven:* `renderDashboard` sets `card.title = \`Open "${p.title}" on the desk\``, so the payload lands in a quoted attribute; `outerHTML` serializes it with a literal `<img`, which is why the raw-html substring check failed while the structural probe reported `handlers == 0, exec == 0`. The check now removes quoted attribute values before looking for a tag (`has_raw_tag`), so it still catches a real tag and can no longer be fooled by an escaped one — 13 tests, 4 of which fail if it is reverted to the substring. *(b) unload leg — a real defect found and fixed:* the pagehide flush was guarded by `if (!ideaSaveTimer) return;`, and `saveIdeaContent()` clears that timer before its POST is sent, so during any in-flight save the flush sent nothing — and the in-flight fetch is the one a pagehide aborts (only keepalive survives). The rule now decides from the text (`unloadFlushPayload` in core.js); the real handler is extracted from app.js and driven in node, 10 tests, 1 fails with the old guard. *(c) live-region repeat leg — unchanged and still unverified:* whether assistive technology re-announces an identical error is not observable from the DOM, which is the suite's own stated position. **Still open:** the Chromium legs were not run — no browser binary is reachable in this environment — so this is not a browser, screen-reader or security pass and does not claim to be.

## 18–20: writer-owned content and history (controlled storage probes)

**18. Concurrent or failed chat-session saves can lose or resurrect conversation data — release blocker for concurrent/deletion safety.** Isolated `SessionStore` tests showed: (a) after two snapshots saved, a repeated user message `Yes` was dropped because merge identifies messages by `(role, content)` rather than turn identity; (b) saving a snapshot after session deletion recreated the session; (c) a stale save after deleting a branch restored that branch; (d) when `Session.load` was made to raise a simulated transient `OSError`, saving a stale snapshot overwrote a newer stored user message; (e) when parking a damaged session as `.bak` was made to fail, save overwrote the damaged original without a backup. These are controlled store-layer reproductions, not proof that every UI flow hits them or of frequency. An in-flight chat can plausibly hold a stale session; actual HTTP timing and cross-process variants remain to be tested. **Recommended:** stable unique message/turn IDs and ordered operation-based merge; monotonic version and durable deletion tombstones for sessions/branches; prevent stale work from recreating deleted data; fail closed or preserve explicit recoverable copies if a merge read/backup fails. Clarify profile deletion independently; test simultaneous turns, repeated identical messages, cancellation, delete while in flight, backup failure, corruption and process restarts. Until fixed, avoid clearing chats or deleting branches while responses are still in flight, and preserve verified private copies of important conversations. **Fixed 2026-11-04 (critique §35).** (a) stable `message_id` + identity-based union, with deterministic legacy ids for older files; (b) durable `<sid>.deleted.json` tombstone written under the session lock, refusing a save only when the snapshot is older than the deletion — note my first two rules here were wrong and broke "clear this chat and start over" for the fixed-id lab thread before the full suite caught it; (e) `save` now fails closed when the damaged copy cannot be parked as `.bak`. (c) and (d) are covered only indirectly by the pre-existing branch tombstone and `OSError` branch and were not independently re-proven. The first version of the (a) test was vacuous — it passed against buggy code because the merge never ran; the committed test reproduces on the disk-holds-a-repeat direction and fails pre-fix.

**19. Stash silently truncates saved writing.** Controlled call to `add_to_stash` with 4,004 characters saved exactly 4,000 and dropped the tail without an error. The UI's success path labels a successful response “Stashed,” but the precise UI selection path and user-visible frequency were not tested here. **Recommended:** preserve full text within an explicit, justified bound; reject too-large inputs before accepting them with a clear message or show a non-destructive preview and require consent to any truncation. Include Unicode, long selections, proposals and API tests. Until fixed, do not rely on Stash for passages exceeding 4,000 characters; retain the original separately. **FIXED 2026-11-05** (critique S53). *Reproduced:* 4,004 characters in, 4,000 saved, tail gone, no error; and the route answered 201, so the UI said "Stashed ✓" and the success record could not express that anything was cut. *Fixed:* the bound stays (4,000, now `MAX_TEXT_CHARS`) but is never silent — over-bound text is refused with a sentence naming both lengths and saying nothing was saved or cut; the bound is served on `GET .../stash` so the selection float refuses before the round trip; and entries the old code cut are reported, not rewritten (`entry_truncated()` reads the evidence from the file and states the original length as unknown rather than inventing a count). *Pinned:* 11 tests in `tests/test_stash_no_silent_truncation.py`; 5 fail with the silent slice restored, 1 with the served bound removed. Unicode, at-the-bound and the proposal path are covered.

**20. Saved beat-board order can appear current when stale.** With a saved order `[2,1]` and mocked current scene numbers `[1,2,3]`, `get_order` returned natural order while `has_board` still returned true; the stored old order remained on disk. This proves the stale-order fallback at the module level, not how a real writer would interpret a particular UI. **Recommended:** bind order to draft/scene identities; explicitly mark stale/unmatched cards and preserve the saved arrangement until the writer reconciles it. Validate same-number/different-scene changes, draft switching and reparse as well as export; never silently overwrite a stale board.

## 98–101: collaborator turn classification, safety prompts and memory scope

**98. Turn classification treats an intent statement as a bare idea, so the collaborator interrogates a writer who just told it what they meant.** `classify_turn` keys on the first word and a trailing question mark only. Measured on the real functions: "Let the silence sit." → `idea`; "I want the audience to feel compulsion." → `idea`; both are then **probed** ("why do you think so?"). By contrast "Can we talk about the mother?" and "Could I lose the last beat?" are classified `question` because they start with a modal, so an exploratory request becomes a question turn and a stated intention becomes a probe target. This is precisely the failure the user's brief rules out: Sameer should not interrogate when the writer has already said what they want or asked something. The reasoning carve-out works only when a connective like "because" is present ("I cut the line." alone still classifies `idea`). **Recommendation:** classify on intent cues, not the first token — add imperative/statement patterns for "let", "I want", "I'd like", "keep", "allow", and treat modal+verb as a request for help rather than a fact question. Keep the probe for genuine undeveloped ideas only, and cover this table with a regression test that uses the writer's own Darshi/Pain 3 phrasing. **FIXED 2026-11-06** (critique S81). *Reproduced exactly as filed*, on the real functions: "Let the silence sit." → `idea` → **probed**; "I want the audience to feel compulsion." → `idea` → probed; and the inverse "Can we talk about the mother?" / "Could I lose the last beat?" → `question`. *Now:* classification carries the distinction instead of `should_probe` growing exceptions — it stays **one line** because `intent` and `request` are no longer `idea`. `intent` (what they want or what they did) is **never probed**; `request` (modal + **first person**) is engaged with and, like a question, **never nudged** (`ensure_forward_momentum`). Each kind has a **behaviour**, not a label: `peer.opening_contract()` now owns the lead-the-reply instructions that used to be an inline string in the engine, so a new kind cannot be added without deciding what the reply does first, and the contract is testable without a model call. *Two boundaries deliberately NOT widened, because the obvious rule is wrong:* "Mara should die at the end" stays a **probeable idea** (effect-vs-event — how the work should *feel* is an intention, what should *happen* is an idea to develop; two pre-existing tests pin it and they are right), and "Can the mother appear earlier?" stays a **question** (no first person ⇒ asking for a judgment, not proposing a change to their own draft). "Let's cut the scene" stays a directive while "Let the silence sit" does not — one apostrophe. *Reverts:* 9 / 4 / 17 / 2 / 1 / 1 / 2 — re-measured after R6 initially passed because the contract was still *called* and then discarded for the new kinds. 33 tests in `tests/test_intent_is_not_an_idea.py`. *Not done:* this is a **pattern table over English**, and it will not cover the writer's Telugu/Tenglish phrasing — "Ammaki cheppakunda vellipothadu" is an intention this classifier will still read as an idea. The brief's rule holds regardless, but the mechanism here is English-only, and `is_english`-style routing is the honest fix rather than more regexes. Also not done: `has_embedded_reasoning` is unchanged, so "I cut the line because it repeated itself" suppresses the probe through the *reasoning* path while "I cut the line" now does it through the *intent* path — two rules, one outcome, and they could drift.

**99. The safety contract for the probe path lives in prompt text only.** `PROBE_SYSTEM_PROMPT` instructs the model to reflect, ask one question and avoid suggestions; that is a good instruction, but nothing deterministic enforces it on the reply. `ensure_forward_momentum` and `cap_suggestions` do post-process, yet they operate on heuristics applied after generation, and the same is true of `reply_transforms`. A model that answers with three suggestions on a probe turn will be partly trimmed, not prevented, and the writer's first impression of Sameer is set by that turn. **Recommendation:** treat the first turn as a contract with a post-check (reflection present, exactly one question, no offer), and when it fails, regenerate once with the violation named rather than silently trimming. Keep the prompt as the primary mechanism.

**100. Craft history can only cite edits that are still applied, so a writer who tries something and reverts it looks like they never did it.** `craft_history` reads `edits.json`, which holds only in-effect edits because undo pops the record onto the redo stack. That is documented honestly in the module, and it is the safest available reading — but it means the collaborator's "last time you cut the explainer line" evidence is silently one-sided: deliberate experiments the writer reversed are invisible, and a writer who undoes a lot will have almost no craft history despite a month of work. **Recommendation:** keep the in-effect rule for what may be *cited*, but derive a separate, never-quoted "experiment count" from the undo/redo stacks so the memory refresh can distinguish "this writer rarely changes lines" from "this writer tries and reverts constantly". Do not let either number become a claim about the person.

**101. Several persona-visible behaviours are decided by substring rules that the writer will read as the collaborator's character.** `has_embedded_reasoning` matches words like "since" and "so that", which also occur in ordinary narration ("since the funeral, he…"); `classify_turn`'s directive list misses polite forms ("could you tighten this", "would you try…") that then route down the question path. These are cheap to fix and high-leverage, because every misfire is experienced as the collaborator not listening. **Recommendation:** replace the substring tests with a small, tested intent table covering requests, permissions, statements of intent, reasoned choices and pure ideas in English, Tenglish and Hinglish (the product already claims those registers), and log the classification per turn locally so a writer's report of "it didn't answer me" can be traced. This pairs with gap 98 and should be implemented as one unit.

Test baseline: pure-function probes of `classify_turn`, `should_probe` and `has_embedded_reasoning`, plus source traces of the probe path and craft-history scope. No model was called; the demo transcripts in gap 92 show what a stand-in does, not what the classification rules guarantee.

## Product direction — the intent problem, stated once without a gap number

The analysis is **intent-blind**: `save_project_premise` persists `premise.json`, the graduation route carries it,
and the collaborator's prompt builder accepts `premise=`, but `Orchestrator.run_analyze` → `pipeline.analyze` takes
only document, client and language options, and "premise"/"intent" appear in `pipeline.py` and `prompts.py` only as
*output* concepts. Scene-level intent has nowhere to live; dismissal records a judgment that feeds back only as a
hidden row. So a writer can state what they meant — in prose meant for this purpose — and neither collaborator
hears it.

That is a product decision for the writer and the collaborator designs to make, not a defect, and it cannot be
validated here without a real model. If it is taken up, the shape is: a scoped, structured intent brief (premise
card + per-scene intent + deliberate flags) passed into the relevant passes; the model stating the intent it
believes it is judging; findings that conflict with stated intent surfaced as *disagreements to discuss* rather
than defects; and Sameer exploring intent while Sushruta tests it against evidence. Evaluated on the writer's own
material, not by this sweep.

**Also product direction:** a writer-facing recovery surface (97's substance). Each failure is honest in its own
endpoint — 503 "not touched", 400 with a reason — but none offers the next action. That is a journey decision, and
the underlying defects are already numbered (80, 82, 70, 64, 72).
